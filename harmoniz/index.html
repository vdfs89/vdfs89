Harmoniz.AI

A digital sommelier that answers wine questions from a real e-commerce catalog instead of the model's memory, so every recommendation names a label that exists, with its price.

The 570 wines are embedded into ChromaDB. A question like "a red under 100 from Chile" becomes a retrieval with a price cap and a country filter, and the answer lists the labels it used. Two heavier modes sit on top: a tool-using agent and a judge that picks the best of three models.

Architecture

Three ways to answer,
one source of truth.

All three modes read from the same ChromaDB collection, so a faster mode never knows about wines the slower ones do not.

Engineering decisions

Four calls worth explaining
in an interview.

01 · Grounding

Answer from the catalog, and show it.

A plain LLM invents labels and prices with confidence. Here the prompt only gets the retrieved wines, and the response lists them by name and price, so a reader can check the answer against the catalog.

02 · Retrieval

Turning "under 100" into a filter.

Semantic search alone is bad at numbers. The question is parsed for a price cap and a country before retrieval, and those become metadata filters on ChromaDB, so "a red under 100 from Chile" never returns a 300 French wine that merely sounds similar.

03 · Judge

A judge that cannot break the answer.

The judge must return JSON naming the winner. If it is unavailable, returns invalid JSON or names a model that did not answer, the system falls back to the first valid response and says why.

If only one candidate answers, the judge is skipped entirely.

04 · Trade-off

Three modes for three budgets.

The fast chat makes one model call. The agent adds tool calls and conversation memory. The judge mode makes four model calls per question, one after another. Keeping them as separate modes lets the user pick between speed and a second opinion, instead of paying for the slowest path every time.

Limitations

What this project
is not.

  • The agent's promotion and stock tools return simulated data from hardcoded tables; only the catalog search tool reads the real data.
  • The judge mode needs Gemini configured and is marked as partial in the README.
  • There is no evaluation set yet: answer quality and latency have not been measured, so this page quotes none.
  • The catalog is a 570-row snapshot; prices and availability are not live.
