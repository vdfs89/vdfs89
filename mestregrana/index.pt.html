MestreGrana

Um assistente de educação financeira que responde a partir dos números do próprio usuário, por texto ou voz, e alterna entre três provedores de LLM para que uma queda não derrube o chat.

Feito em Streamlit em volta de um dashboard, relatórios financeiros (DRE, fluxo de caixa, análise de variância), um simulador de produtos e uma página de auditoria. O chat injeta o perfil de investidor, as metas e as últimas transações do usuário em cada prompt e manda o modelo dizer quando o dado não existe.

Arquitetura

Feito para continuar
respondendo.

O app foi refatorado em core, services, repositories e components, para que as páginas do Streamlit só renderizem e o fallback de provedores fique num módulo só.

Decisões de engenharia

Quatro decisões que valem explicar
numa entrevista.

01 · Disponibilidade

Três provedores, uma função.

Planos gratuitos de LLM limitam e caem. O chat chama o call_llm_with_fallback, que tenta o Llama 3.3 no Groq, depois o Gemini, depois o GPT-4o-mini, e devolve a primeira resposta. Cada chamada tem timeout; o caminho de um provedor só tenta de novo com backoff exponencial.

Colocar isso num único módulo do core fez o chat de texto e o de voz ganharem a mesma resiliência sem esforço extra.

02 · Ancoragem

Responder pelos números do usuário.

Em vez de conselho genérico, cada prompt leva a renda, as metas, a reserva de emergência e as últimas transações do usuário, mais a instrução de dizer quando falta informação em vez de chutar o saldo.

As respostas por voz ficam em uma a três frases, porque são para ser ouvidas.

03 · Dados

Uma demo que não precisa de credenciais.

O perfil, os produtos e as transações que o chat lê vêm de arquivos de exemplo versionados, carregados por funções em cache com TTL curto. O Postgres no Neon, com pool de conexões e health checks, guarda os registros de auditoria e consentimento; o MongoDB Atlas é opcional.

Assim a demo pública e o desenvolvimento local rodam sem nenhum segredo de banco, e o painel de status mostra quais serviços estão configurados.

04 · Estrutura

De um script grande para camadas.

A primeira versão era um único arquivo de Streamlit. A refatoração da v2 dividiu em core (logging, cache, clientes de LLM), services (loaders em cache), repositories (Postgres e Mongo) e components (gráficos, tabelas, voz).

Dependências opcionais, como as de áudio, são importadas sob demanda, então um pacote ausente desliga uma funcionalidade em vez de derrubar o app.

Limitações

O que este projeto
não é.

  • É um chat de um modelo com fallback de provedor, não um sistema multiagente: não há orquestração de agentes nem um modelo que audite a resposta de outro.
  • A ancoragem é a injeção dos dados do usuário no prompt, não uma busca numa base de conhecimento; a qualidade das respostas não foi avaliada.
  • A demo pública roda só com dados de exemplo; é uma ferramenta de educação, não aconselhamento financeiro regulado.
  • O hash de senha usa SHA-256 com salt; uma versão de produção deveria migrar para um hash lento, como bcrypt ou Argon2.
