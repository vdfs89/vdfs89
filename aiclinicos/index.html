AIClinicOS

A platform that coordinates AI agents for a clinic's scheduling, patient messages, clinical notes and reporting, sold per clinic, with each clinic's data isolated in the database itself.

Published as DrPilot OS. The most instructive part of the project was not a feature: an audit of the claims against the live database found that a sprint marked as delivered had never reached production, and the README now separates what is verified from what is not.

Architecture

Agents on top,
isolation underneath.

Requests that touch patients, appointments or documents pass one tenant ownership guard; clinical approvals and copilot interactions go to append-only tables; reminders and jobs run in a separate worker.

Engineering decisions

Three calls worth explaining
in an interview.

01 · Verification

Checking the database, not the backlog.

The sprint that delivered the clinical audit log was marked done. Checking production showed the Supabase migration ledger was empty: the database had never been built from the repository's migrations, and the table did not exist.

The schema was reconciled migration by migration against information_schema. The audit log now refuses updates at the database level, not by convention.

02 · Isolation

RLS that was on but did nothing.

The function behind 23 row-level security policies compared identifiers from two different key spaces and denied everything. It failed closed, so nothing leaked, but patient tables had RLS enabled with no real isolation behind it.

After the fix, cross-clinic access was tested in production with real bearer tokens: two users, two synthetic tenants, every read, write and export of the other clinic refused.

03 · Safety

Refuse to start without keys.

In production and staging the backend will not boot without a valid encryption key. There is no silent fallback to a development key, because a clinic that runs with the wrong key is worse than a clinic that does not run.

Limitations

What this project
is not.

  • No real patient note has gone through the clinical audit path yet; the infrastructure is tested against the database, not against clinical traffic.
  • Calendar sync has never been validated end to end with a real Google or Microsoft account.
  • CFM and LGPD compliance are not claimed as a fact; the WhatsApp integration is migrating to Meta's official Cloud API.
  • Part of the financial analytics reads database objects that are not yet applied in production.
