AIClinicOS

Uma plataforma que coordena agentes de IA para agenda, mensagens aos pacientes, notas clínicas e relatórios de uma clínica, vendida por clínica, com os dados de cada clínica isolados no próprio banco.

Publicado como DrPilot OS. A parte mais instrutiva do projeto não foi uma funcionalidade: uma auditoria das afirmações contra o banco em produção descobriu que uma sprint marcada como entregue nunca tinha chegado lá, e o README agora separa o que está verificado do que não está.

Arquitetura

Agentes por cima,
isolamento por baixo.

Requisições que tocam pacientes, consultas ou documentos passam por uma única guarda de posse por tenant; aprovações clínicas e interações do copiloto vão para tabelas append-only; lembretes e tarefas rodam num worker separado.

Decisões de engenharia

Três decisões que valem explicar
numa entrevista.

01 · Verificação

Conferir o banco, não o backlog.

A sprint que entregava o log de auditoria clínica estava marcada como concluída. Conferindo a produção, o ledger de migrações do Supabase estava vazio: o banco nunca tinha sido construído pelas migrações do repositório, e a tabela não existia.

O schema foi reconciliado migração por migração contra o information_schema. O log de auditoria agora recusa UPDATE no nível do banco, não por convenção.

02 · Isolamento

RLS ligada que não fazia nada.

A função por trás de 23 policies de row-level security comparava identificadores de dois espaços de chave diferentes e negava tudo. Falhava fechado, então nada vazou, mas as tabelas de pacientes tinham RLS ligada sem isolamento real por trás.

Depois da correção, o acesso entre clínicas foi testado em produção com bearer tokens reais: dois usuários, dois tenants sintéticos, toda leitura, escrita e exportação da outra clínica recusada.

03 · Segurança

Recusar subir sem chave.

Em produção e staging o backend não sobe sem uma chave de criptografia válida. Não há fallback silencioso para chave de desenvolvimento, porque uma clínica rodando com a chave errada é pior que uma clínica parada.

Limitações

O que este projeto
não é.

  • Nenhuma nota de paciente real passou ainda pelo caminho de auditoria clínica; a infraestrutura foi testada contra o banco, não contra tráfego clínico.
  • A sincronização de agenda nunca foi validada de ponta a ponta com uma conta Google ou Microsoft real.
  • Conformidade com CFM e LGPD não é afirmada como fato; a integração com WhatsApp está migrando para a Cloud API oficial da Meta.
  • Parte da análise financeira lê objetos de banco que ainda não foram aplicados em produção.
