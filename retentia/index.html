Projects / 06 · Telecom · Churn prediction

RetentIA

A churn classifier for a telecom operator where the interesting part is not the network but the threshold: it is set by what each kind of mistake costs.

Built for FIAP's Machine Learning Engineering program, Phase 1, on the IBM Telco Customer Churn dataset (about 7,000 customers, 19 features). A PyTorch MLP is compared against dummy, logistic regression and XGBoost baselines in MLflow, served by FastAPI with Pydantic and Pandera validation, and deployed with Docker and Nginx.

Engineering decisions

Four calls worth explaining
in an interview.

01 · Cost

Pricing the two kinds of mistake.

Missing a churner loses the customer's future revenue; flagging a loyal customer wastes one retention offer. With the false negative costing more, the best threshold falls below 0.5.

The threshold is the one that minimizes total cost on the validation set, not on test, and the costs are labeled as example values to be replaced by real customer lifetime value.

02 · Honesty

Saying the MLP did not win.

The challenge required a PyTorch MLP. It reached the same ROC-AUC as logistic regression and lost to XGBoost on F1 and PR-AUC. The model card states this plainly.

It also notes that applying the same cost-tuned threshold to XGBoost would raise its recall too. The contribution is the decision framework, not the network.

03 · Data

A missing value with a reason.

TotalCharges arrives as text, with 11 blank rows. Instead of dropping them or filling with the mean, the ingest checks that they are exactly the customers with tenure 0, who were never billed, and imputes 0.0.

It is structural missingness, not random, and the ingest logs a warning if a future file breaks that pattern.

04 · Contracts

Validation at both doors.

Requests go through a Pydantic v2 schema whose 19 fields use Literal types, so an unexpected category is rejected with a 422 instead of producing a silent prediction.

Training data goes through a Pandera schema built from features/columns.py, the module that also drives preprocessing. The API schema still lists its values separately, a duplication worth removing.

Limitations

What this project
is not.

  • Costs of 500 and 100 are example values. With real lifetime value and campaign cost, the threshold must be recomputed.
  • Probabilities are not calibrated. The threshold compensates, but the raw score should not be read as a true churn probability.
  • The deployed MLP weights predate the training seed, so retraining reproduces the method but not those exact weights.
  • ROC-AUC plateaus around 0.84 to 0.85 for every model, as in the literature on this dataset; going further needs new features or data.
  • Performance by subgroup (gender, senior citizens) has not been measured yet.
